# MVP Backlog

## 1. 文档目的

本文件将 `product-requirements-document.md` 和 `development-task-book.md` 进一步拆解为可执行的 MVP backlog，便于产品、研发、数据、合规和研究角色协同排期。

## 2. 规划原则

- 只拆解已进入 PRD 范围的能力
- 统一治理，分市场执行
- 优先处理授权、证据、审批、审计四类阻塞项
- 每条 backlog 必须能映射到明确交付物和验收标准

## 3. 优先级定义

| 优先级 | 含义 |
|---|---|
| P0 | 不完成则 MVP 无法启动或无法合规上线 |
| P1 | MVP 核心能力，影响主要用户闭环 |
| P2 | 增强能力，可在 MVP 后半段或下一阶段完成 |

## 4. 阶段与 Epic 总览

| 阶段 | Epic | 优先级 | 目标 |
|---|---|---|---|
| S0 | 文档与治理基线 | P0 | 固定范围、角色、流程和验收 |
| S1 | 数据授权与接入 | P0 | 建立三市场合规数据输入 |
| S1 | 证据链与主体映射 | P0 | 建立研究事实层 |
| S2 | 研究卡与评分系统 | P1 | 输出可用研究结论 |
| S2 | 双语 benchmark | P0 | 建立抽取质量门槛 |
| S3 | 决策治理与审计 | P0 | 建立投委会与审批闭环 |
| S3 | CEO Dashboard | P1 | 建立经营与例外入口 |
| S4 | 复盘、图谱与 challenger | P1 | 建立学习闭环 |
| S4 | 事故剧本与演练 | P1 | 建立反脆弱能力 |

## 8. 完成定义 DoD

每条 backlog 完成时，至少满足以下条件：

- 已有明确输出物
- 已通过对应角色评审
- 已记录验收结果
- 已补充到相关文档或系统配置
- 如涉及合规、prompt、数据权限或审计，必须有留痕
