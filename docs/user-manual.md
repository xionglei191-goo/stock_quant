> **一句话介绍**：这是一个用 AI 帮你研究股票、分析市场、做投资决策的"虚拟基金公司"系统。
> 它能自动抓取中国 A 股、港股、美股的公开数据，帮你分析哪些股票值得关注，但**不会真的帮你买股票**——所有交易都只是模拟，必须人工批准才能执行。

## 1. 这个系统是做什么的？

### 1.1 用一句话理解

想象你开了一家"虚拟基金公司"，这家公司有 AI 员工帮你：

- 📊 **收集数据**：自动从网上抓取股票价格、公司公告、财报等公开信息
- 🔍 **分析研究**：用 AI 分析这些数据，找出哪些股票可能值得投资
- 📝 **写研究报告**：自动生成投资建议和分析报告
- ⚖️ **做决策**：帮你评估投资方案，但最终决定权在你手里
- 🎮 **模拟交易**：用虚拟资金模拟买卖，看看策略效果如何

### 1.2 它能覆盖哪些市场？

| 市场 | 简称 | 举例 |
|------|------|------|
| 中国 A 股 | A | 贵州茅台(600519)、宁德时代(300750) |
| 港股 | H | 腾讯(00700)、美团(03690) |
| 美股 | U | 苹果(AAPL)、微软(MSFT)、英伟达(NVDA) |

### 1.3 重要限制

⚠️ **这个系统不会真的帮你买卖股票！** 所有交易都只是"纸上谈兵"（模拟交易），就像你在手机上玩模拟炒股一样。要真正下单，必须有真人审批同意。

## 2. 系统是怎么搭建的？

### 2.1 整体结构 — 像一栋大楼

你可以把这个系统想象成一栋 **5 层大楼**：

```
🏙️ 系统大楼

第5层  👀 前端界面（你看得见的部分）
      │    仪表盘、研究工作台、投资委员会、策略实验室...
      │    就像大楼的"窗户"，让你看到里面发生的事
      │
第4层  🚦 API 路由层（接待大厅）
      │    收到你的请求，检查你有没有权限，然后把你带到正确的房间
      │    就像大楼的"前台"，负责分流访客
      │
第3层  🧠 业务逻辑层（核心办公区）
      │    所有重要的分析、计算、决策都在这里完成
      │    就像大楼里的"各部门办公室"
      │
第2层  🔌 连接器 + 存储层（仓库 + 供应商通道）
      │    连接外部数据源（股票交易所、财经网站等）
      │    把数据存起来（就像仓库）
      │
第1层  🏗️ 基础设施（地基和配套设施）
         数据库、搜索引擎、AI 服务、文件存储...
         就像大楼的"水电煤气"
```

## 3. 数据是怎么流动的？

### 3.1 数据的一生 — 从"原材料"到"成品报告"

数据在系统里要经过 **9 个阶段**，就像工厂的流水线：

```
🏭 数据工厂流水线

阶段1  📥 原料采购（数据采集）
  │    从网上抓取股票价格、公告、财报等
  │    就像去超市买菜
  │
阶段2  🔍 质检入库（数据摄取）
  │    检查数据是否合法，然后存进仓库
  │    就像买回来的菜要洗一洗、检查一下再放冰箱
  │
阶段3  🔬 切菜备料（证据提取）
  │    把长篇大论的文档切成小段有用的信息
  │    就像把大块肉切成小块，方便后面做菜
  │
阶段4  🧠 厨师烹饪（分析研究）
  │    把各种信息综合起来，做出分析结论
  │    就像厨师把各种食材做成一道菜
  │
阶段5  ✅ 品尝鉴定（决策审批）
  │    分析结果需要多人品尝确认
  │    就像菜做好后要先让人尝尝好不好吃
  │
阶段6  🎮 模拟上桌（模拟执行）
  │    用虚拟资金模拟交易
  │    就像先做一份"试吃版"看看效果
  │
阶段7  📊 顾客反馈（组合管理）
  │    跟踪投资组合的表现
  │    就像收集顾客反馈，看看菜卖得好不好
  │
阶段8  💾 存档记录（数据存储）
  │    所有过程都记录下来
  │    就像把每天的销售记录存档
  │
阶段9  📺 上菜展示（界面展示）
       把结果展示给用户看
       就像把做好的菜端上桌
```

### 3.2 股票价格数据怎么来？

#### A 股数据流（中国股票）

```
来源1: BaoStock（证券数据接口）
  │
  │  脚本: scripts/import_ashare_eod_baostock.py
  │  怎么用: python scripts/import_ashare_eod_baostock.py --dsn "数据库地址"
  │  会做什么:
  │    1. 连接 BaoStock 接口
  │    2. 获取指定股票的历史价格（每天的开盘价、最高价、最低价、收盘价、成交量）
  │    3. 自动创建公司和证券记录
  │    4. 存入数据库的 market_data_bars 表
  │
  └─ 数据格式: security_id + 日期 + 开盘价 + 最高价 + 最低价 + 收盘价 + 成交量

来源2: TDX vipdoc（通达信本地文件）
  │
  │  脚本: scripts/import_tdx_vipdoc_postgres.py
  │  怎么用: python scripts/import_tdx_vipdoc_postgres.py --dsn "数据库地址" --vipdoc-path ./data/local/tdx/vipdoc
  │  会做什么:
  │    1. 读取本地通达信 .day 二进制文件（每个记录 32 字节）
  │    2. 解析二进制数据（日期、价格、成交量）
  │    3. 批量写入数据库（每批 5000 条）
  │
  └─ 数据格式: 二进制文件，每个股票一个文件，比如 sh600519.day（贵州茅台）
```

#### 美股数据流

```
来源: Yahoo Finance（雅虎财经）
  │
  │  脚本: scripts/import_us_eod_yahoo_chart.py
  │  怎么用: python scripts/import_us_eod_yahoo_chart.py --dsn "数据库地址" --tickers AAPL,MSFT,NVDA
  │  会做什么:
  │    1. 访问 https://query1.finance.yahoo.com/v8/finance/chart/{股票代码}
  │    2. 获取历史价格数据
  │    3. 存入数据库
  │
  └─ 默认跟踪: AAPL(苹果), MSFT(微软), NVDA(英伟达), TSLA(特斯拉), SPY(标普500 ETF)
```

### 3.3 文档和研报怎么处理？

#### 文档处理流程

```
原始文档（PDF、公告、研报）
        │
        ▼
┌───────────────────┐
│ 第1步: 摄取        │  ← 检查数据来源是否合法
│ (ingest_document)  │  ← 存储文件到仓库
│                    │  ← 计算文件指纹（SHA256）
└────────┬──────────┘
         │
         ▼
┌───────────────────┐
│ 第2步: 提取证据    │  ← 从文档中提取有用信息
│ (extract_evidence) │
└────────┬──────────┘
         │
         ├──────────────────────────────────────────┐
         │                                          │
         ▼                                          ▼
    文档有文字？                              文档是扫描件？
    │                                         │
    ├─ 有 → 直接提取文字                      ├─ 有 OCR 服务 → 调用 PaddleOCR
    │        按段落切分                        │                识别图片中的文字
    │        标记位置和可信度                   │
    │                                         └─ 没有 → 放入人工复核队列
    └─ 没有 → 尝试解析 PDF 文件                       等人工来看
              │
              ├─ 解析成功 → 提取文字
              │
              └─ 解析失败 → 调用 OCR 识别
                           │
                           ├─ 成功 → 提取文字
                           │
                           └─ 失败 → 人工复核
```

**生活类比**：就像你收到一封很长的信，系统会帮你：
1. 先检查这封信是不是正规渠道来的（数据来源合法吗？）
2. 把信的内容存起来（存档）
3. 把重要的句子标出来（提取证据）
4. 如果信是手写的（扫描件），用 OCR 识别手写字
5. 如果实在看不懂，就放到"需要人工处理"的文件夹里

### 3.4 数据存储在哪里？

所有数据都存在 PostgreSQL 数据库里，使用一种叫"文档存储"的模式：

```
📦 数据库就像一个大仓库

┌─────────────────────────────────────────────────────────┐
│  ai_quant.records（总仓库）                               │
│                                                          │
│  每条记录有三个字段：                                      │
│    collection（分类）  item_id（编号）  payload（内容JSON）  │
│                                                          │
│  就像仓库里的货架：                                       │
│    第1层: sources（数据来源）── 50多个分类                   │
│    第2层: issuers（公司信息）                               │
│    第3层: securities（证券信息）                            │
│    第4层: documents（文档）                                │
│    第5层: evidence（证据）                                 │
│    ...                                                   │
│    第50层: alert_rules（告警规则）                          │
│                                                          │
├─────────────────────────────────────────────────────────┤
│  ai_quant.market_data_bars（价格专用仓库）                 │
│                                                          │
│  专门存放股票价格数据，有专门的列：                          │
│    股票代码 + 数据来源 + 数据类型 + 日期                    │
│    开盘价 + 最高价 + 最低价 + 收盘价 + 成交量               │
│                                                          │
├─────────────────────────────────────────────────────────┤
│  ai_quant.audit_log（操作记录本）                          │
│                                                          │
│  记录谁在什么时候做了什么：                                 │
│    操作者 + 操作 + 资源类型 + 资源ID + 时间戳               │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

**为什么用这种设计？**
- 灵活：可以随时添加新的数据类型，不用改表结构
- 简单：所有数据都用同一张表，管理方便
- 高效：PostgreSQL 的 JSONB 格式查询很快

## 4. 系统怎么做决策？

### 4.1 投资决策的 6 道关卡

在系统里，一个投资建议要经过 **6 道关卡** 才能最终执行，就像过安检一样：

```
🔐 投资决策安检流程

关卡1  📜 数据权限检查
  │    "这个数据我能用吗？"
  │    检查数据来源是否有合法授权
  │    ────────────────────────
  │    就像：去图书馆借书，先看看这本书能不能外借
  │
  ▼ 通过？
  │
关卡2  🔬 证据质量检查
  │    "这些信息可靠吗？"
  │    从文档中提取的证据要经过质量评估
  │    ────────────────────────
  │    就像：写论文时，引用的资料要可靠
  │
  ▼ 通过？
  │
关卡3  📊 评分检查
  │    "这只股票值得投资吗？"
  │    系统给股票打分（0-1分）
  │    分数 >= 阈值 → "建议买入"
  │    分数 < 阈值 → "建议观望"
  │    ────────────────────────
  │    就像：考试打分，60分以上及格
  │
  ▼ 通过？
  │
关卡4  ⚖️ 合规检查
  │    "这个决策合法合规吗？"
  │    检查是否违反信息披露规定
  │    检查是否使用了未公开信息
  │    ────────────────────────
  │    就像：开车前检查有没有驾照、有没有违章
  │
  ▼ 通过？
  │
关卡5  ✍️ 双签审批
  │    "有人同意吗？"
  │    需要两个人签字：
  │      - 风控人员（必须）
  │      - CEO 或 CIO（必须）
  │    ────────────────────────
  │    就像：重要决定要两个人签字才生效
  │
  ▼ 通过？
  │
关卡6  🎮 模拟执行
       "用虚拟资金试试看"
       系统强制使用模拟模式
       记录：成交价、数量、滑点、手续费
       ────────────────────────
       就像：先用模拟炒股软件试试，不用真钱
```

### 4.2 关卡1 详解：数据权限检查

每个数据都有一个"权限标签"（RightsTag），就像食品包装上的"保质期"和"食用说明"：

```
📋 权限标签包含：

training_allowed     → 能用来训练 AI 模型吗？（能/不能）
redistribution_allowed → 能转发给别人吗？（能/不能）
display_use          → 能在界面上显示吗？（能/不能）
non_display_use      → 能用于后台分析吗？（能/不能）
derived_data_use     → 能基于它生成新数据吗？（能/不能）
```

**检查规则**：数据使用者的权限需求 <= 数据提供者的权限范围

举个例子：
```
数据来源：BaoStock（免费公开数据）
  权限：允许训练、允许转发、允许显示、允许后台分析

你的需求：想用这个数据做投资分析
  需要：允许后台分析 ✓

结果：通过！因为你的需求在允许范围内
```

如果数据来源不允许某种用途，系统会**直接拒绝**，不会偷偷用。

### 4.3 关卡2 详解：证据提取

系统从文档中提取证据时，有一套"降级策略"——就像考试时，第一种方法不行就用第二种：

```
📝 证据提取策略（按优先级）

策略1: 直接提取文字
  │  文档本身就是文字（比如公告正文）
  │  → 直接按段落切分，标记位置
  │
  │  不行？↓
  │
策略2: 解析 PDF 文件
  │  文档是 PDF 格式
  │  → 解析 PDF 内部的操作符（TJ/Tj）
  │  → 提取文字内容
  │
  │  不行？↓
  │
策略3: 用 OCR 识别
  │  文档是扫描件（图片）
  │  → 调用 PaddleOCR 云服务
  │  → 把图片中的文字识别出来
  │  → 自动重试（最多 3 次）
  │
  │  不行？↓
  │
策略4: 人工复核
     实在提取不出来
     → 放入"人工复核队列"
     → 等人工来处理
```

### 4.4 关卡3 详解：股票评分

系统给股票打分的方法叫"评分卡"（Scorecard），就像老师给学生打分：

```
📊 评分卡示例

因子1: 营收增长      权重: 30%  ← 营收增长越快，分数越高
因子2: 净利润        权重: 25%  ← 利润越高，分数越高
因子3: 毛利率        权重: 20%  ← 毛利率越高，分数越高
因子4: 经营现金流    权重: 15%  ← 现金流越好，分数越高
因子5: 风险因子      权重: 10%  ← 风险越低，分数越高

最终分数 = 因子1分数 × 30% + 因子2分数 × 25% + ...

方向判断：
  分数 >= 0.7（阈值可配置）→ "建议买入" (long)
  分数 <= 0.3            → "建议卖出" (short)
  其他                   → "建议观望" (neutral)
```

### 4.5 关卡4 详解：合规检查

系统会检查投资决策是否合法合规：

```
⚖️ 合规检查清单

✓ 不能使用未公开信息做交易决策（遵守信息披露规定）
✓ 不能交易有权限限制的数据源对应的证券
✓ 不能使用"仅限内部使用"的数据做公开决策
✓ 所有决策必须有审计记录
✓ 所有 AI 操作必须有人工复核标记
```

如果违反了任何一条，系统会返回 HTTP 423 错误（合规门控阻断），就像门禁卡刷不开门一样。

### 4.6 关卡5 详解：双签审批

重要决策需要**两个不同角色的人**签字：

```
✍️ 审批流程

第1步: 系统生成决策包（DecisionPack）
  │    包含：投资信号、风控检查结果、红队分析
  │    状态：pending（等待审批）
  │
第2步: 风控人员签字
  │    检查风险是否可控
  │    添加批注
  │
第3步: CEO 或 CIO 签字
  │    确认投资方向
  │    添加批注
  │
第4步: 两人都签字后
  │    状态变为：approved（已批准）
  │
第5步: 才能创建执行意图（ExecutionIntent）
       然后进行模拟执行
```

### 4.7 关卡6 详解：模拟执行（硬约束）

这是系统最严格的约束——**绝对不能真的交易**：

```
🎮 模拟执行的硬性规定

代码层面强制：
  - 如果有人试图设置 mode="live"（真实交易）
  - 系统会直接抛出 ComplianceGateError 错误
  - 就像汽车的限速器，物理上不可能超速

模拟执行会记录：
  - 成交价（模拟的市场价格）
  - 成交数量
  - 名义金额
  - 滑点（价格变动的影响）
  - 手续费

所有记录都会存档，方便事后复盘
```

```
  │

  ▼
备用方案3: 放入人工复核队列

额外规则:

  - 关键风险任务：始终需要人工复核
```

### 4.9 工作流怎么运行？

系统可以定义"工作流"，就像工厂的流水线：

```

特点：
```

### 4.10 告警系统怎么工作？

系统会监控各种指标，发现异常就报警：

```
🚨 告警流程

  │    例如："LLM 错误率 > 10% 就报警"
  │    规则包含：指标名、比较符、阈值、严重程度

  │    获取当前指标值
  │    和阈值比较
  │

  │    创建 SystemAlert（系统告警）
  │    关联 IncidentPlaybook（应急手册）
  │

  │    auto_action: 自动执行（比如重启服务）
  │    manual_action: 需要人工处理
  │    rollback_action: 回滚操作
  │

```

成功响应：
```json
{
  "success": true,
  "data": {

  },
  "error": null,
```

错误响应：

### 8.3 监控指标

系统会监控这些关键指标：

| 指标 | 正常范围 | 异常时怎么办 |
|------|---------|-------------|
| 健康状态 | `status: "ok"` | 检查数据库连接、服务状态 |
| 存储类型 | `store: "PostgreSQLStore"` | 检查 PostgreSQL 是否运行 |
| A 股最新日期 | 3 天内 | 检查 BaoStock 连接、数据导入脚本 |
| 美股最新日期 | 5 天内 | 检查 Yahoo Finance 连接 |
| LLM 错误率 | < 10% | 检查 AI 服务、API 密钥 |
| LLM 回退率 | < 20% | 检查 AI 服务稳定性 |
| LLM 预算使用率 | < 80% | 考虑增加预算或优化使用 |
| 告警数量 | 0 个 critical | 检查具体告警原因 |

### 8.4 错误类型说明

| 错误类型 | HTTP 状态码 | 含义 | 怎么办 |
|---------|-----------|------|--------|
| `ValidationError` | 422 | 输入数据格式错误 | 检查请求参数 |
| `NotFoundError` | 404 | 找不到请求的资源 | 检查 ID 是否正确 |
| `ConflictError` | 409 | 数据冲突（比如重复） | 检查是否已存在 |
| `PermissionDenied` | 403 | 没有权限 | 检查角色设置 |
| `ComplianceGateError` | 423 | 违反合规要求 | 检查是否符合规定 |
