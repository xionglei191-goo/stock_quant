# 按角色拆分的执行包

## 1. 文档目的

本文件将 `mvp-backlog.md` 按团队角色拆分，便于直接指派 owner、安排并行工作和控制跨职能依赖。

## 2. CEO / CIO / PM

### CEO

- 拍板三市场范围、非目标和自动执行边界
- 批准公开来源红黄绿分级规则
- 确认例外事项池和月度经营回顾机制

交付物：

- 范围确认记录
- 预算与例外审批口径
- CEO 月报模板确认

### CIO

- 定义公司研究卡、行业研究卡和双评分卡口径
- 定义投委会 Pack 模板、反方流程和复盘模板
- 确认 13F 只用于拥挤度和风控

交付物：

- 研究卡模板
- 双评分卡模板
- 投委会 Pack 模板
- 复盘模板

### PM

- 维护跨文档一致性
- 维护 `tasks/todo.md`
- 跟踪依赖、阻塞项和周节奏

交付物：

- 待办清单
- 周状态同步
- 里程碑验收记录

## 3. 合规 / 风险

### 合规负责人

- 建立三市场公开来源矩阵
- 定义 training、redistribution、display、non-display 边界
- 建立 Reg FD 审查规则和 prompt 审批规则

交付物：

- 公开来源 provenance 台账
- Reg FD 审查规则
- prompt 审批 SOP

### 风险负责人 / CRO

- 定义风险校验节点和例外事项池
- 定义 challenger 闸门和高风险结论拦截规则
- 编写五类事故剧本并安排演练

交付物：

- 风险校验清单
- challenger 冲突规则
- 事故剧本和演练计划

## 4. 数据 / 平台

### 数据工程

- 接入 A/H/U 三市场公开披露源
- 接入公开/已提供 EOD/延时数据
- 建立原始资料入湖和元数据记录

交付物：

- ingestion 清单
- 原始资料库存储规范
- 数据源元数据字典

### 平台负责人

- 建立 Thesis Card schema
- 建立主体映射规则
- 建立统一审计日志字段
- 建立知识图谱 schema

交付物：

- schema 文档
- 主体映射规则
- 审计日志字典
- 图谱 schema

## 5. NLP / ML

### NLP/ML 负责人

- 建立中文公告/年报 benchmark
- 建立英文 SEC 披露抽取 benchmark
- 定义 benchmark 上线门槛
- 构建 challenger 提示模板与冲突评分规则

交付物：

- benchmark 样本与标注规范
- 基线评测报告
- 上线门槛说明
- challenger 规则文档

## 6. 产品 / 前端

### 产品负责人

- 设计 CEO Dashboard、三市场主体页、投委会页
- 定义页面字段和用户动作

交付物：

- 页面字段清单
- 页面原型或组件清单

### 前端负责人

- 实现 Dashboard
- 实现主体页
- 实现投委会页和例外事项池

交付物：

- 页面实现列表
- 状态与错误处理规则

## 7. 研究团队

### 分析师 / 海外研究负责人

- 参与证据链 schema 设计
- 提供公司研究卡和行业研究卡样本
- 参与中文/英文 benchmark 标注
- 维护反证样本和挑战者样本

交付物：

- 研究卡样本
- 标注样本
- 反证样本库

## 8. 并行建议

可并行开展：

- 合规做公开来源矩阵时，数据工程可准备接入清单
- NLP 做 benchmark 时，平台可做 schema 和日志字段
- CIO 做评分卡时，产品可做页面字段设计
- 风险写事故剧本时，PM 可同步建立演练日历

必须串行的关键点：

- 没有公开来源矩阵，数据源不能进入生产链路
- 没有 benchmark 门槛，抽取模型不能进入事实层
- 没有审计和审批规则，投委会流程不能进入可执行层
