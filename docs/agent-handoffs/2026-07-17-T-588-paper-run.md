## Objective

Implement deterministic, replayable dynamic-allocation paper decision snapshots without broker connectivity, order creation, or live execution.

## Scope

- In scope: validated snapshot contract, point-in-time lineage checks, fractional-Kelly/risk audit details, hash-chained JSONL adapter, dry-run-first CLI, focused tests.
- Out of scope: API routes, central database integration, UI, broker adapters, order intents, and claims that a 6-12 month operating period has elapsed.

## Background

T-588 requires every paper decision to retain the exact data, factors, model state, sizing constraints, allocation, configuration, and explanation available at the decision time. The broader application integration is owned by the parent agent.

## Problem Statement

A target allocation alone is not auditable. Replaying it requires immutable point-in-time observation identifiers, factor lineage, model and configuration versions, Kelly inputs, named risk caps, and structural enforcement of the paper-only boundary.

## Expected Deliverables

- `app/dynamic_allocation/paper/snapshot.py`: deterministic snapshot builder and validation.
- `app/dynamic_allocation/paper/repository.py`: append-only, hash-chained local JSONL repository and replay validation.
- `scripts/dynamic_allocation_paper_run.py`: no-write default and explicit-output execution mode.
- `tests/dynamic_allocation/test_paper_run.py`: point-in-time, governance, integrity, idempotency, replay, and CLI tests.

## Current Findings

- The run ID is a deterministic SHA-256-derived identity over normalized decision content; `evaluated_at` defaults to `as_of` for deterministic replay.
- Observations with `available_at > as_of`, future factor cutoffs, or unknown factor lineage IDs are rejected.
- Factor configuration hashes must match the decision configuration hash.
- Kelly must be `quarter` or `half`; full Kelly is rejected. Named component caps and sizing explanations are mandatory.
- The final equity allocation must equal the minimum of requested, available Kelly, risk, and maximum caps. SPY plus QQQ must equal final equity; SGOV completes the portfolio.
- SQQQ and all non-Phase-1 assets are rejected from persistent long-term allocations.
- Identical run IDs are explicit no-op duplicates. Ledger content or chain tampering prevents replay.

## Risks

- JSONL is a local adapter, not a concurrency or retention substitute for the central database in a multi-process deployment.
- The hash chain detects mutation but is not a digital signature; a user controlling the file can replace the entire ledger.
- No 6-12 month observation period has elapsed. This task implements the capability and audit trail only.
