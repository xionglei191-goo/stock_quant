## Objective

## Background

T-587 delivered the API-only Streamlit page and T-588 validated it using a temporary process. The main `/ui` retained a direct `http://127.0.0.1:8501` link, but the production-like Compose stack never declared a dashboard service.

## Problem Statement

The dashboard process was absent after later service switches. The image also lacked Streamlit and the governed config directory, while the dynamic SQLite default resolved outside the mounted data volume. A global `ApiRouter` lock let unrelated long requests block health checks and all dynamic-allocation reads.

## Decisions

- Keep Streamlit as an independent API-only service. It does not read the primary state store and uses `http://ai-quant-org:8000` inside Compose.
- Use `/dynamic-allocation` as the stable UI entry and an HTTP 302 rather than embedding or proxying Streamlit. This preserves WebSocket behavior and lets local, LAN, and reverse-proxied deployments select the correct host.
- Retain the main `SystemService` dispatch lock because its trace context, in-memory collections, dirty-set bookkeeping, audits, and commits are shared mutable state.
- Give `/api/dynamic-allocation/*` a separate serial lock because `DynamicAllocationApplication` owns a separate SQLite domain repository. Dynamic usage telemetry is recorded only when the main lock is immediately available, so telemetry never turns into a response blocker.
- Let `/api/health` bypass business dispatch locking because it is a no-side-effect descriptor read and is excluded from usage telemetry.

## Risks and Open Questions

- The current live decision returns `ready=false`, `freshness=incomplete`, and 4/8 available factors. This is a governed data-freshness state, not a page/runtime failure; refreshing source data is outside T-625.
- Dashboard port 8501 is published on all host interfaces, matching the existing port-8000 local/LAN posture. Non-local deployment still requires the repository's production authentication and reverse-proxy controls.
- Dynamic routes remain serialized with each other to protect their SQLite repository. T-625 removes cross-domain contention, not all serialization.
- The first image build downloaded large Streamlit/PyArrow dependencies; subsequent builds reuse Docker layers unless the dependency layer changes.
