# 公司情报与市场综合分析平台 PRD

- Status: active
- Owner group: PM / Release Coordination
- Last updated: 2026-06-24
- Related tasks: T-431, T-432, T-433, T-434, T-435, T-436
- Scope: 产品定位、目标用户、核心流程、功能范围、成功指标和阶段路线
- Non-goals: 真实券商接入、自动下单、实时量化交易、把研报当作事实源或训练源

## 1. Purpose

本文档统一项目的新产品定位：本系统是本地优先的公司情报与市场综合分析平台，用于为每只股票/公司建立可追溯的结构化和非结构化数据库，支持研究观察、结论记录、观点复盘和模拟反馈。

本轮重定位保留既有行情、财务、披露、研报、证据、图谱、模拟 ledger 和审计能力，但主流程不再围绕组织角色、审批签字或执行意图展开。旧的决策治理对象只作为兼容模块存在，当前 UI 和 API 主路径已重编排到公司情报工作台。

## 2. Product Positioning

### 2.1 Product Name

公司情报与市场综合分析平台。

### 2.2 Product Definition

面向个人研究者和分析用户的全天候公司数据库与市场分析系统。系统把公开披露、本地行情、财务数据、研报、新闻、政策、产业链、网页证据和个人研究记录组织成公司级画像、事件时间线、关系图谱、观点样本库和模拟反馈闭环。

### 2.3 Core Value

- 为每只股票/公司建立持续更新的公司画像，而不是只在分析时临时拼数据。
- 将行情、财务、公告、事件、关系和非结构化材料统一入湖，并保留来源、时间和证据回链。
- 把研报作为关注度信号、观点样本库和分析师可靠性复盘来源。
- 将个人假设、观察任务、分析结论和模拟交易结果连接起来，用反馈验证研究是否有效。
- 保留数据可信度、权限边界和审计日志，确保结论能被复盘和纠错。

## 3. Target Users

| User | Primary Goal | System Support |
|---|---|---|
| 个人研究者 | 从全市场收窄到值得观察的公司 | 研报覆盖、事件热度、主题关联、筛选和观察池 |
| 投资分析用户 | 快速理解公司、事件和关系 | 公司画像、事件时间线、关系图谱、多源证据 |
| 复盘用户 | 判断观点、机构和自己的分析是否可靠 | 研报观点追踪、分析师评分、分析结论复盘 |
| 数据维护者 | 保持数据可回链、可更新、可审计 | 来源治理、入湖状态、证据定位、质量报告 |
| 产品/平台维护者 | 让后续 agent 按统一方向迭代 | 任务路线、架构文档、schema 和交接记录 |

## 4. Core Workflow

主流程固定为：

```text
数据入湖 -> 公司画像 -> 事件时间线 -> 关系图谱 -> 多源观点 -> 观察任务 -> 分析结论 -> 模拟反馈
```

流程说明：

1. 数据入湖：采集或登记公开/本地/明确提供的数据，记录来源、用途边界、采集时间、原文对象和证据定位。
2. 公司画像：围绕公司主体和证券建立基础信息、行业、财务、行情、公告、研报覆盖和数据完整度视图。
3. 事件时间线：把公告、财报、新闻、政策、订单、诉讼、价格异动、供需变化等统一成可回链事件。
4. 关系图谱：连接公司、证券、人物、机构、产品、产业链节点、客户、供应商、竞争、股权和主题关系。
5. 多源观点：结构化研报、个人笔记、模型摘要和外部观点，明确事实、推断、预测和主观判断边界。
6. 观察任务：把值得跟踪的问题、触发条件、证据缺口和后续催化剂沉淀为任务。
7. 分析结论：记录研究假设、结论、信心、证据、反证、有效期和复盘计划。
8. 模拟反馈：用 paper-only ledger 记录假设对应的模拟操作或观察组合，后续用行情和事件验证结论质量。

## 5. Product Scope

### 5.1 In Scope

- A/H/U 公司、证券、公告、披露、行情和财务数据的本地优先入湖。
- 公司画像、事件时间线、关系图谱和证据回链。
- 研报资产登记、解析、观点结构化、目标价/评级/盈利预测追踪。
- 机构和分析师维度的预测兑现、观点变化和可靠性评分。
- 个人观察池、观察任务、分析结论、反证和复盘记录。
- 模拟交易/模拟持仓 ledger，作为分析有效性反馈工具。
- 数据来源治理、rights tag、cache retention、审计和质量报告。
- 本机长期使用、备份恢复和非本机发布证据附录。

### 5.2 Out of Scope

- 真实券商 API、真实委托、自动下单和自动调仓。
- 高频或秒级交易系统。
- 将研报、转录稿或边界不清第三方材料用于模型训练。
- 将研报结论直接当作事实真相。
- 用组织角色、投委会签批或执行意图作为主产品流程。

## 6. Research Report Role

研报是一等公民，但它属于观点层和关注度信号，不属于事实真相源。

研报的核心用途：

- 关注池筛选：当公司进入多家机构覆盖或重点报告视野，说明市场关注度变化，系统应提示观察。
- 观点结构化：抽取机构、分析师、评级、目标价、核心假设、盈利预测、估值方法、催化剂、风险和后续验证点。
- 可靠性复盘：跟踪观点兑现、目标价达成、盈利预测误差、评级调整滞后和分析师覆盖质量。
- 多源对照：把研报观点与公告、财报、监管披露、行情、新闻和个人观察对照，而不是单独采信。

研报边界：

- 研报可以进入观点样本库、观察池和复盘评分。
- 研报不能直接覆盖事实层字段。
- 事实层必须回链公告、财报、交易所/监管披露、公司 IR、公开行情或其他可信来源。
- 边界不清或受限研报只能进入本地参考，不进入训练、再分发或自动事实抽取层。

## 7. Functional Requirements

### 7.1 Data Lake and Source Governance

Requirements:

- 所有数据源记录 `source_id`、`source_type`、`source_uri`、`collection_method`、`rights_tag`、`usage_scope`、`retention_policy` 和 `last_reviewed_at`。
- 边界不清的数据进入 manual reference，不进入事实层和训练层。
- 支持本地对象存储、状态库、检索索引和可复验 artifacts。

Acceptance:

- 新入湖对象可以追溯到原始来源和采集时间。
- 红区或边界不清内容不会自动升级为事实或训练样本。

### 7.2 Company Profile

Requirements:

- 以 `issuer_id` 和 `security_id` 为中心建立公司画像。
- 聚合基础信息、证券映射、行业/板块、财务摘要、行情摘要、公告摘要、研报覆盖、事件摘要和关系摘要。
- 标记每个画像字段的来源、更新时间、置信度和缺口。

Acceptance:

- 任一重点公司可看到结构化画像和缺失数据清单。
- 公司画像字段可回链到来源和证据。

### 7.3 Event Timeline

Requirements:

- 支持公告、财报、新闻、政策、订单、诉讼、价格、供需、管理层变化和资本动作等事件类型。
- 每个事件记录 `event_id`、`issuer_id`、`security_id`、`event_type`、`occurred_at`、`source_ids`、`evidence_ids`、`confidence` 和 `impact_tags`。
- 事件可以被观察任务、观点和模拟反馈引用。

Acceptance:

- 事件按时间线展示，并能回链原文。
- 事件能与研报观点、个人结论和模拟表现交叉复盘。

### 7.4 Relationship Graph

Requirements:

- 支持公司、证券、人物、机构、产品、产业链节点和主题节点。
- 支持客户、供应商、竞争、股权、机构覆盖、分析师覆盖、上下游和主题关联。
- 关系记录来源、有效期、方向、权重和置信度。

Acceptance:

- 公司页可以展示主要关系和证据来源。
- 关系变化可以进入事件时间线和观察任务。

### 7.5 Viewpoint and Report Intelligence

Requirements:

- 支持 `ResearchReport`、`ReportViewpoint`、`ReportForecast`、`AnalystProfile` 和 `AnalystReliabilityScore`。
- 研报字段必须覆盖机构、分析师、发布时间、标的、报告类型、评级、目标价、当前价、核心假设、盈利预测、估值方法、催化剂、风险和后续兑现状态。
- 支持按机构、分析师、公司、主题、评级变化和目标价变化查询。

Acceptance:

- 研报观点结构化率可统计。
- 分析师预测复盘覆盖率和误差可统计。

### 7.6 Observation and Analysis

Requirements:

- 支持 `ObservationItem` 记录观察对象、问题、触发条件、证据缺口、owner、due date 和状态。
- 支持 `AnalysisConclusion` 记录结论、假设、证据、反证、信心、有效期、复盘计划和关联观察任务。
- 结论必须区分事实、推断、预测和主观判断。

Acceptance:

- 每条分析结论能回链数据、事件、关系和观点。
- 到期结论有复盘状态。

### 7.7 Simulation Feedback

Requirements:

- 支持 `SimulationFeedback` 将分析结论与模拟操作、观察组合、收益表现、事件验证和复盘结论连接。
- 模拟交易仅用于反馈分析有效性，固定 `paper_only=true` 和 `live_execution_allowed=false`。
- 支持记录不交易的观察反馈，例如“只观察，不模拟买入”。

Acceptance:

- 模拟反馈可回链到原始分析结论。
- 反馈结果可用于修正分析流程、研报可靠性和观察任务，不触发真实订单。

## 8. Success Metrics

| Metric | Definition | Target Direction |
|---|---|---|
| 公司画像覆盖率 | 重点公司画像字段已填充并有来源的比例 | 越高越好 |
| 事件回链率 | 公司事件拥有原文证据或可信来源的比例 | 越高越好 |
| 研报观点结构化率 | 已入库研报中完成核心观点字段抽取的比例 | 越高越好 |
| 分析师预测复盘覆盖率 | 可复盘预测中完成兑现/误差计算的比例 | 越高越好 |
| 分析结论复盘完成率 | 到期结论完成复盘的比例 | 越高越好 |
| 模拟反馈可回链率 | 模拟反馈能回链到结论、事件和证据的比例 | 越高越好 |
| 边界违规数 | 研报/受限材料进入事实层、训练层或真实交易触发的次数 | 必须为 0 |

## 9. Information Architecture

目标 UI 应以公司情报工作台为中心：

- 总览：观察池、重点事件、研报覆盖变化、待复盘结论和模拟反馈。
- 公司页：公司画像、行情/财务、事件时间线、关系图谱、研报观点、观察任务。
- 事件页：事件列表、来源证据、影响标签、相关公司和后续验证。
- 关系图谱：产业链、客户供应商、机构/分析师覆盖、股权和主题关联。
- 观点库：研报观点、个人假设、外部观点和可靠性评分。
- 复盘页：分析结论、模拟反馈、目标价兑现、预测误差和经验记录。
- 数据治理：来源、权限、缓存、证据质量和入湖状态。

旧的组织运营台、签批页和执行意图视图只作为兼容入口，不再作为默认导航主路径。

## 10. Non-Functional Requirements

### 10.1 Traceability

- 事实、事件、关系、观点、结论和反馈必须保留 source/evidence/linkage。
- 任何摘要或模型输出必须记录 model/prompt/version/fallback 信息。

### 10.2 Data Boundary

- 公共、本地或明确提供的数据优先。
- 边界不清数据只能人工参考。
- 研报和第三方转录稿不得作为训练源或自动事实源。

### 10.3 Reliability

- 本机长期使用应支持备份、恢复、覆盖审计和质量包复验。
- 非本机组织级发布证据保留为运维附录，不阻塞个人研究产品路线。

### 10.4 Extensibility

- 状态库、对象存储、检索、图谱、向量检索和编排应可替换。
- 当前单体服务可通过 facade 逐步拆分，保持 API 兼容。

## 12. Risks and Open Questions

- 现有代码和 UI 中仍有旧命名，后续增强需要继续以兼容迁移方式重命名，避免一次性破坏 API。
- 研报解析字段抽取质量需要人工样本和复盘闭环验证。
- 公司关系图谱容易产生低置信推断，必须保留来源和置信度。
- 模拟反馈可能被误解为交易建议，UI 和 API 都必须明确 paper-only 边界。
- 非本机组织级发布门禁仍有价值，但应从产品主路线下沉到运维附录。
