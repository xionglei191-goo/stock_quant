# 产品需求文档 PRD

## 1. 文档目的

本文档用于统一 AI Native 虚拟量化基金组织项目的产品目标、范围、能力要求、阶段规划和验收标准。PRD 基于以下研究与项目文档整理而成：

- `docs/deep-research-report.md`
- `docs/deep-research-report-加美股.md`
- `docs/deep-research-report -next.md`
- `docs/project-support.md`
- `docs/risk-register.md`
- `docs/development-task-book.md`

## 2. 产品概述

### 2.1 产品名称

AI Native 虚拟量化基金组织

### 2.2 产品定位

一个面向 A/H/U 三市场、中低频、公开信息驱动、人工审批执行的研究增强型投研与组合管理系统。

### 2.3 核心价值

- 把分散的公开披露、授权数据和研究证据组织成可审计的研究流程。
- 用统一治理框架管理 A/H/U 三市场，但保留分市场执行逻辑。
- 把研究、反方、合规、审批、复盘串成闭环，而不是只做分析问答工具。

## 3. 背景与问题

现有研究文档已证明项目方向可行，并明确提出以下新要求：

- 项目范围从 A/H 双市场扩展到 A/H/U 三市场。
- 美股模块要求新增 SEC EDGAR、10-K/10-Q/8-K、20-F/6-K、13F、Reg FD、non-display 等能力边界。
- 下一步落地重点不再只是系统架构，而是数据授权矩阵、双语 benchmark、组合框架、权限治理、事故剧本、反方自动化和统一知识图谱。

当前问题：

- 研究结论多，产品范围和阶段能力边界还没有在一份 PRD 中统一。
- 三市场差异和双语处理要求尚未映射为清晰的产品功能与非功能需求。
- 新增研究项目群尚未转化为正式产品阶段和验收标准。

## 4. 产品目标

### 4.1 业务目标

- 建立三市场统一的研究与治理底盘。
- 提升研究结论的证据回溯能力和复盘能力。
- 将投委会、风控和合规要求前置到系统流程中。

### 4.2 产品目标

- 支持 A/H/U 三市场主体、披露、事件、观点和持仓的统一管理。
- 支持中英双语披露的原文定位、摘要生成和审计留痕。
- 支持长线/短线双评分卡、事件驱动和拥挤度分析。
- 支持投委会决策包、prompt 审批、例外事项和事故处理。

### 4.3 成功指标

- 证据覆盖率 >= 95%
- 关键研究结论原文回链率 >= 95%
- 未审批 prompt 变更数 = 0
- 红区数据自动入库训练数 = 0
- 高风险结论 challenger 覆盖率 = 100%

## 5. 目标用户与角色

| 角色 | 主要目标 |
|---|---|
| CEO | 看经营、看风险、批例外、控边界 |
| CIO | 组织研究、形成决策包、协调策略 |
| PM | 管理组合建议、仓位和执行意图 |
| 风险/合规 | 控权限、控限额、控版权、控合规 |
| 分析师 | 输出研究卡、证据链和反证材料 |
| 海外研究负责人 | 管理美股、ADR、中概与双语研究 |
| NLP/ML 负责人 | 管理 benchmark、抽取质量和 challenger |
| 平台负责人 | 管理数据、日志、权限和稳定性 |

## 6. 产品范围

### 6.1 包含范围

- A/H/U 三市场公开披露接入
- A/H/U 授权 EOD/延时数据接入
- 证据链、研究卡、Thesis Card
- 长线/短线双评分卡
- SEC 时间线、8-K 事件墙、13F 拥挤度热图
- 投委会 Pack、电子签字、例外审批
- benchmark、事故剧本、反方自动化
- A/H/U 统一知识图谱

### 6.2 不包含范围

- 自动下单
- 高频/秒级交易
- 未授权实时 non-display 数据
- 未授权研报和第三方转录的训练化使用
- 脱离人工审批的仓位调整

## 7. 产品原则

- 研究先于交易
- 原文先于摘要
- 合规先于效率
- 治理先于模型复杂度
- 统一治理，分市场执行
- 长短线分仓、分评分、分 KPI

## 8. 功能需求

### 8.1 数据与授权管理

功能要求：

- 建立三市场授权矩阵，记录 `source_type`、`license_class`、`training_allowed`、`redistribution_allowed`、`retention_policy`
- 对美股数据增加 `display_use`、`non_display_use`、`derived_data_use` 标签
- 接入 A/H/U 公开披露和授权 EOD/延时数据

验收标准：

- 所有生产数据源均可映射到授权台账
- 红区数据默认阻断自动入库训练

### 8.2 主体映射与知识图谱

功能要求：

- 建立 A/H/U 统一主体模型
- 支持 LEI、FIGI、CIK、本地代码映射
- 支持 Company、Security、Filing、Metric、Event、View、Position 节点关系

验收标准：

- 样本主体映射准确率 >= 98%
- 观点到证据回溯率 >= 95%

### 8.3 文档解析与证据链

功能要求：

- 支持中文公告/年报和英文 SEC 披露解析
- 支持术语、数值、期间、证据页、原文片段定位
- 支持研究卡、行业卡和 Thesis Card 统一 schema

验收标准：

- 关键术语抽取与证据定位达到 benchmark 门槛
- 任一研究结论可查看原文依据

### 8.4 研究与评分

功能要求：

- 支持长线/短线双评分卡
- 支持事件驱动和 13F 拥挤度分析
- 支持中英双语情绪与风险因素变化检测

验收标准：

- 长短线评分独立运行
- 13F 只用于拥挤度和风控，不直接作为交易触发

### 8.5 反方与风险治理

功能要求：

- 支持 Red Team 和 challenger 模型
- 支持 ConflictScore 规则和反证库
- 支持 Reg FD 闸门、non-display 闸门和权限审批

验收标准：

- 高风险结论 challenger 覆盖率 100%
- 可疑来源不能进入可执行建议层

### 8.6 决策与审批

功能要求：

- 支持投委会 Pack
- 支持电子签字和审批链
- 支持例外事项池和拒绝入库机制

验收标准：

- 未签字建议不得进入执行意图
- 所有关键操作有审计日志

### 8.7 复盘与经营系统

功能要求：

- 支持月度经营回顾模板
- 支持收益、研究质量、治理健康三类指标
- 支持复盘报告、策略回放和事故 RCA

验收标准：

- 月报固定出具
- 每个红灯项有责任人和截止时间

## 9. 页面与交互需求

### 9.1 CEO Dashboard

必须展示：

- 组合总览
- 风险热图
- 例外事项池
- SEC 时间线
- 8-K 事件墙
- 13F 拥挤度热图

### 9.2 三市场主体页

必须展示：

- A/H/U 相关证券
- 最近公告与 filings
- 财务指标与证据链
- 投委会历史
- 风险状态与评分结果

### 9.3 投委会页

必须展示：

- 推荐动作
- 核心证据
- 反方意见
- 风险意见
- 审批状态

## 10. 非功能需求

### 10.1 合规

- 不允许未授权数据进入事实层和训练层
- 不允许未通过 Reg FD 审查的内容进入可执行建议

### 10.2 审计

- 记录 actor、time、model_version、prompt_version、source、approval_state

### 10.3 可解释性

- 所有研究结论必须能定位到原文或结构化证据

### 10.4 可扩展性

- 模型、向量库、工作流引擎可替换
- 支持从 batch-first 逐步升级到 Feast/Kafka

## 11. 阶段规划

### 阶段 1

- 三市场授权矩阵
- A/H/U 原始披露接入
- rights tagging
- 证据链 schema

### 阶段 2

- 中文/英文 benchmark
- 长短线双评分卡
- 13F 拥挤度
- CEO Dashboard 初版

### 阶段 3

- 投委会 Pack
- challenger
- prompt 审批
- Reg FD 与 non-display 闸门

### 阶段 4

- 知识图谱
- 复盘系统
- 月度经营回顾
- 事故演练体系

## 12. 依赖与风险

关键依赖：

- 数据授权台账
- benchmark 与抽取基线
- 三市场主体映射规则
- 审批与日志标准

关键风险：

- 授权不清
- non-display 误用
- 双语抽取幻觉
- 主体映射错误
- challenger 失效

详细登记见 `docs/risk-register.md`。

## 13. 验收标准

- PRD 覆盖三市场范围、数据边界、能力清单、阶段和验收
- 支持文档、风险登记册、任务书和 PRD 相互一致
- 每个阶段都有明确输出物和入口/出口条件
- 核心非目标写清楚，避免范围失控
