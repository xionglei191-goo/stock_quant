# 开发任务书

## 一、项目概述

本任务书面向 AI Native 虚拟量化基金组织的 MVP 建设，目标是在 A/H/U 三市场范围内，先完成研究增强与决策治理，再逐步进入组合闭环。

## 二、开发原则

- 研究先于交易。
- 人工审批先于自动执行。
- 事实源优先于摘要源。
- 统一治理，分市场执行。
- 双语原文优先于翻译摘要。
- 权限、审计、版权优先于功能扩张。
- 模型可替换，治理不可缺。

## 三、阶段划分

### 阶段 0: 文档与治理基线

目标：把项目边界、角色、验收与变更机制固定下来。

任务：

- 建立文档索引与项目支持文档。
- 固化项目范围和非目标。
- 定义 RACI、审批链和例外流程。
- 建立风险登记模板。

验收：

- 所有核心文档可互相引用。
- 角色责任明确到人。

### 阶段 1: 数据与证据链

目标：跑通“原始材料 -> 清洗 -> 证据链 -> 研究卡”。

任务：

- 接入 A/H/U 三市场公开披露、年报、中报、10-K、10-Q、8-K、20-F、6-K 和公开/已提供数据。
- 为每条数据打 rights tag。
- 建立 display/non-display、training_allowed、redistribution_allowed 标签。
- 建立文档解析、去重、标准化流程。
- 建立 Thesis Card、证据链 schema 和三市场主体唯一键。

验收：

- 任一研究结论都可回链到原始资料。
- 边界不清来源不能进入事实层。
- A/H/U 主体映射可用于统一检索和归因。

### 阶段 2: 研究与评分

目标：形成公司、行业、宏观与情绪的统一研究工作流。

任务：

- 建立公司研究卡和行业研究卡模板。
- 建立长线/短线双评分卡。
- 建立中文公告/年报 benchmark 和英文披露抽取基线。
- 建立 13F 拥挤度、事件驱动和双语情绪补充模块。
- 建立反证字段和 Red Team 机制。
- 建立 CEO Dashboard 的核心视图。

验收：

- 同一标的可输出研究结论、反方意见和评分结果。
- 长短线评分可独立计算。
- benchmark 达到上线阈值，且抽取结果可定位原文。

### 阶段 3: 决策治理

目标：把研究包变成可签字的投委会决策包。

任务：

- 建立投委会 Pack 生成流程。
- 建立审批流、电子签字和审计日志。
- 建立 prompt 变更审批、Reg FD 闸门和 non-display 审查规则。
- 建立风险/合规校验节点。
- 建立例外事项面板。

验收：

- 任一调仓建议必须经过审批。
- 未签字建议不得进入执行意图。
- 高风险结论必须经过 challenger 或人工复核。

### 阶段 4: 复盘与迭代

目标：让系统能学习、能回放、能修正。

任务：

- 建立复盘报告模板。
- 建立归因、误差分解和策略回放。
- 建立挑战者模型池。
- 建立月度经营回顾模板。
- 建立 A/H/U 统一知识图谱和版本化查询接口。

验收：

- 每次重大决策都能追踪结果和偏差原因。
- 策略或模型更新有记录、有依据。
- 观点、证据、持仓和主体关系可以回查。

## 五、依赖关系

- 数据接入依赖 provenance、rights tagging 和 non-display 审查。
- 研究卡依赖证据链 schema、主体映射和 benchmark。
- 投委会 Pack 依赖研究卡、评分卡、风险校验和 Reg FD 闸门。
- 执行意图依赖审批流、审计日志和例外机制。
- 复盘依赖完整的过程日志、结果数据和知识图谱。

## 六、主要风险

- 数据公开来源边界不清导致版权和合规风险。
- 研究卡缺乏统一 schema 导致结论不可比。
- 审批流失效导致组织黑箱化。
- 指标只看收益导致治理质量下降。
- 双语抽取不稳定导致事实层污染。
- 三市场主体映射错误导致研究与持仓错连。

## 七、里程碑

| 里程碑 | 目标 | 结果 |
|---|---|---|
| M1 | 文档基线完成 | 项目边界清晰 |
| M2 | 数据与证据链跑通 | 三市场研究结论可回链 |
| M3 | 审批流跑通 | 决策可签字、可拦截 |
| M4 | 图谱与复盘闭环 | 系统可迭代、可回查 |

- PDF 对象文本流/Flate 流抽取兜底，已可从本地对象存储 PDF 生成证据切片。
- 术语、数值、期间和规则表格读取基线抽取；可按中英 benchmark 样本集运行术语 F1、页命中、数值/期间、表格、定位和低置信度拦截评估。
- 证据切片、Thesis Card、评分、投委会 Pack、签字、复盘、例外事项。
- Execution Intent 审批闸门；未审批决策不能进入执行意图。
- benchmark、prompt 审批、research card、13F crowding、challenger、事故剧本和演练日历。
- 可选 SQLite 状态库；设置 `AI_QUANT_DB` 后，核心对象、签字链和审计日志可跨服务重启保留。
- PostgreSQLStore runtime；设置 `AI_QUANT_POSTGRES_DSN` 或 PostgreSQL DSN 形式的 `AI_QUANT_DB` 后，使用生产状态库基线 schema、通用 JSONB records、独立审计表、核心索引和便捷视图。
- SQLite -> PostgreSQL 显式迁移脚本；`scripts/migrate_sqlite_to_postgres.py` 读取 SQLiteStore 并重写目标 PostgreSQL records/audit。
- 对象存储 adapter；默认本地对象存储，`AI_QUANT_OBJECT_STORE_BACKEND=s3` 时可写入 S3 兼容对象存储；文档入湖记录 `object_uri` 与 `content_sha256`。
- 批量 ingestion job；支持 connector normalize、去重、错误留痕、任务状态查询。
- Evidence extraction 支持分页文本定位；`\f` 分页会写入 `page_no` 和 `page=...;chunk=...` locator。
- 解析失败分级和人工复核队列；空文本/扫描件类文档会生成 `ManualReviewItem`，并可通过 evidence quality report 查看定位覆盖率、平均置信度和解析失败率。
- 英文 evidence 优先的研究问答与中文摘要审计；`ResearchAnswer` 保留英文原文、中文摘要、summary 版本、prompt 版本、模型版本、来源公开性和人工覆核状态。
- Black-Litterman 纸面组合原型；`PortfolioProposal` 保留均衡先验、后验收益、候选权重、观点置信度/Omega、风险预算、禁投清单、压力测试和 walk-forward 诊断，只生成投研候选方案，不绕过投委会生成纸面执行意图或模拟持仓流水。
- `/ui` 静态单页界面，覆盖目标运营台总览、CEO Dashboard、主体页、投委会页、A/H/U 预览、结构化抽取、采集调度和事故日历；左侧信息架构和顶部市场/风险/冲突状态已按 `pic/UI.png` 补齐。
- UI 静态验收脚本；`scripts/ui_static_check.py` 检查目标信息架构、顶部状态、关键面板 ID 和前端脚本语法。
- `/api/demo/full-flow` 可生成一套端到端展示数据。
- 月度经营报告和策略回放记录，覆盖治理指标、研究质量指标、公开行情驱动的模拟组合绩效指标、红灯项、发布审批、偏差原因、版本和后续动作。
- 检索 adapter；默认内置全文检索 fallback，可跨 Document、Evidence、Thesis、Research Card 搜索，`AI_QUANT_SEARCH_BACKEND=opensearch` 时可写入和查询 OpenSearch 兼容后端。
- 最小部署健康检查和运行指标接口，覆盖 `/api/health` 与 `/api/metrics`。
