# 开发就绪清单

## 1. 目标

判断项目是否已经具备进入代码开发阶段的最小条件。

## 2. 就绪标准

### 2.1 需求就绪

- [x] 已有 PRD
- [x] 已有 MVP backlog
- [x] 已有按角色执行包
- [x] 已有待办清单

### 2.2 架构就绪

- [x] 已有系统架构设计
- [x] 已有数据结构设计
- [x] 已有接口契约
- [x] 已有降级策略

### 2.3 治理就绪

- [x] 已有支持文档
- [x] 已有风险登记册
- [x] 已有开发任务书
- [x] 已有审查结论

### 2.4 执行就绪

- [x] 已有代码前待办清单
- [x] 已有角色分工
- [x] 已有里程碑与验收口径

## 3. 开发启动前必须确认的事项

- 公开来源 provenance 矩阵是否可执行
- benchmark 样本是否可开始标注
- 主体映射主键是否已确认
- 审计日志字段是否已冻结
- Reg FD 与 non-display 审查规则是否可用
- prompt 审批链是否可执行
- Dashboard 首批页面是否冻结

## 4. 首批代码仓建议目录

```text
app/
  api/
  services/
  domain/
  workers/
  ui/
docs/
tasks/
infra/
tests/
```

## 5. 首批开发顺序

1. 基础配置与目录骨架
2. 数据源注册与公开来源矩阵
3. 原始文档入湖与证据抽取
4. Thesis Card 与主体映射
5. benchmark 与评分引擎
6. 投委会 Pack 与审计日志
7. CEO Dashboard

## 6. 进入代码开发的判断

当以下条件满足时，可以进入代码开发阶段：

- 核心需求无歧义
- 主键与 schema 已冻结
- 接口契约已定义
- 合规闸门已定义
- 第一批任务可按模块拆分给开发者
